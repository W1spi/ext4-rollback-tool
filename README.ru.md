# ext4-rollback-tool

Инструмент для создания снапшотов и отката (rollback) для Linux-систем на ext4, построенный на основе rsync с дедупликацией через hardlink (`--link-dest`).

---

## Обзор

ext4-rollback-tool — это **лёгкая и предсказуемая система отката**, предназначенная для Linux-окружений, где ext4 используется как основная файловая система.

Позволяет:

- сохранять состояние системы за секунды
- безопасно восстанавливаться после сломанных конфигураций или обновлений
- отдельно откатывать Docker-инфраструктуру
- обходиться без тяжёлых технологий (Btrfs, ZFS, LVM)

> Основной фокус — **контроль, прозрачность и надёжность**, а не абстракция.

---

## Зачем этот проект

Большинство решений предполагают:

- современные файловые системы (Btrfs / ZFS)
- использование LVM
- полноценные backup-системы (borg, restic и т.д.)

Однако в реальных условиях:

- ext4 по-прежнему является стандартом
- переход на другую файловую систему часто невозможен
- backup-инструменты слишком тяжёлые для быстрых откатов

Этот проект решает:

> **быстрый, локальный и предсказуемый rollback на ext4 без изменения инфраструктуры**

## Быстрый старт (1–2 минуты)

```bash
git clone git@github.com:W1spi/ext4-rollback-tool.git
cd ext4-rollback-tool

# подготовка конфигурации (дефолты уже безопасны)
cp config/*.env.example config/*.env

# включение таймеров
chmod +x bin/apply-timers.sh
sudo ./bin/apply-timers.sh

# создание первых снапшотов (опционально)
sudo ./bin/snapshot-system.sh
sudo ./bin/snapshot-docker.sh
```

### Готово.

Теперь снапшоты:

- автоматически запускаются через systemd
- сохраняются в `/var/backups/ext4-rollback`
- готовы к использованию для отката в любой момент

---

### Расположение проекта

Директорию проекта можно разместить в любом месте:

- `/opt/ext4-rollback-tool`
- `/home/user/ext4-rollback-tool`
- или любой другой путь

Жёстких путей нет — всё поведение настраивается через конфигурационные файлы.

---

### Настройка (опционально)

Если нужно изменить пути, количество хранимых снапшотов или расписание:

```bash
nano config/snapshot-system.env
nano config/snapshot-docker.env
nano config/timers.env
```

## Важно

Это **НЕ система резервного копирования**.

Она НЕ защищает от:

- выхода диска из строя
- потери данных

Она предназначена исключительно для:

> **быстрого отката локального состояния системы**
