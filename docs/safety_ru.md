# Safety

Этот документ описывает механизмы безопасности системы снапшотов и восстановления.

Система спроектирована так, чтобы минимизировать риск повреждения системы,
ошибочного восстановления и потери данных.

---

## Общая философия

Восстановление — это потенциально опасная операция.

Поэтому система следует принципу:

> Невозможно выполнить разрушительное действие без явного осознания и подтверждения пользователем

---

## Ключевые механизмы защиты

### 1. Dry-run перед применением

Перед реальным восстановлением система:

- строит план изменений через rsync --dry-run
- показывает список изменений
- отображает статистику (создания / удаления / изменения)

---

## Понимание rsync dry-run

Перед применением restore система строит план изменений через:

```bash
rsync --dry-run --itemize-changes ...
```

---

### Пример вывода

```
>f.st...... etc/ssh/sshd_config
>f+++++++++ etc/new_config.conf
*deleting   etc/old_config.conf
```

---

## Расшифровка формата

Каждая строка имеет формат:

```
XY........ путь
```

---

### Основные символы

| Символ | Значение |
|--------|----------|
| f      | файл |
| d      | директория |
| L      | симлинк |
| +      | новый объект |
| s      | изменён размер |
| t      | изменено время |
| c      | изменён checksum |

---

### Типы операций

| Префикс       | Значение |
|---------------|----------|
| >f            | файл будет обновлён |
| >f+++++++++   | новый файл будет создан |
| .d            | директория без изменений |
| *deleting     | файл/директория будет удалён |

---

## Важный момент

Ключевая опция:

```bash
--delete
```

означает:

> всё, чего нет в снапшоте — будет удалено из системы

---

## На что обращать внимание

Перед restore обязательно проверяйте:

- массовые удаления (*deleting)
- изменения в:
  - /etc
  - /usr
  - /boot

Если видите что-то неожиданное:

→ НЕ запускайте restore

---

### 2. Анализ опасных удалений

Система отдельно анализирует удаления в критических директориях:

- /etc
- /usr
- /boot
- /lib
- /bin
- /sbin

---

### 3. Двойное подтверждение

Для system restore требуется:

1. Ввести "yes"
2. Ввести имя снапшота

---

### 4. Разделение restore

- system restore
- docker restore

---

### 5. Excludes restore-system (двойной замок)

Исключаются:

- /proc
- /sys
- /dev
- /run
- /mnt
- /media
- /var/lib/docker

---

### 6. Проверка снапшота

Проверяется:

- структура
- ключевые файлы
- размер

---

### 7. Логирование

Фиксируется:

- пользователь
- время
- снапшот

---

### 8. Root-only

Только root может запускать restore

---

## Рекомендации

- всегда смотреть dry-run
- не делать restore "вслепую"
- хранить снапшоты вне /

---

## Ограничения

Система НЕ заменяет backup.

---

## Итог

Система безопасна, но требует осознанного использования.
